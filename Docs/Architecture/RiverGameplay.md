# V3 river gameplay

Run `Assets/Game/Gameplay/Scenes/V3Gameplay.unity` with two Relay peers. Start the game on the host. At the mountain-side lower dock, approach the water edge and press E to board the linked raft. The HUD identifies your assigned oar. W and S row in either direction. Hold Shift with W or S for a stronger stroke that consumes stamina. Both players must board before the raft starts moving. While the raft is at its departure berth, E or Esc can cancel boarding. At the fortress-side upper dock, arrival releases both riders and separates the hulls.

The solo rafts board at the upper dock after the server enters Return. The DEV Return button is available in Editor and Development builds. Each player rows independently and uses A/D to steer. Both use the original channel. The current is faster in Return and carries unpowered rafts downstream. The river records the order of arrival locally to the session. Course victory remains a game-state responsibility.

`RiverGameplay` binds the saved V3 water ribbon and the two saved dock colliders. The water follows increasing world Z from lower to upper, while the current points downstream. The server owns raft snapshots, steering, hazard encounters, recovery, split state and arrival rank. Player movement remains owner-authoritative and derives the seated pose from the replicated hull view. Source prefab instances are visual children of runtime wrappers. The level generator and its saved geometry can be reviewed independently.

The departure dock is the recovery point. Five damaging contacts reset the linked raft and both players together. Three reset the affected solo rider and hull. Whirlpool forces can increase transit time and never count as damage. Enemy warnings show where the lunge is aimed. The damage event exposes the location and cause for presentation. The existing F3 overlay shows river simulation diagnostics in Development builds and the Editor.

For static validation use **Tools > Twin Edge > Gameplay > Validate Saved River**. To run the two-peer scripted crossing in a Windows Development build, use `-riverReplay host` and `-riverReplay client` with the same fresh `-riverEvidence <absolute ignored directory>`. Leave graphics enabled and add `-riverScreenshots` for the rendered run. The replay positions both characters at the lower dock for setup and then sends ordinary keyboard input. The run does not establish manual play acceptance. Optional local logs and notes live under `Docs/Development/Gameplay/V1/`.
