# V3 멀티플레이

## Relay와 NGO

두 프로세스는 별도 익명 Unity Authentication 프로필을 사용한다. Host는 Relay 할당 및 참가 코드를 만들고 NGO Host로 동작하며, Client는 같은 코드를 통해 Relay에 접속한다. Unity Services 설정이 공유 프로젝트에 연결되어 있어야 한다. 참가 UI는 레벨을 로드한 뒤 열리며, 두 피어는 씬 바인딩, 승인된 스폰 적용, 네트워크 캐릭터와 카메라 초기화가 완료되면 서버에 Ready를 보고한다. 서버는 사용자 Ready, Host 시작 승인, 두 Runtime Ready가 모두 충족되면 경기 시작 구간을 연다.

`MultiplayerSessionManager`는 방과 연결을 관리하고, `NetworkSpawnCoordinator`가 플레이어 오브젝트를 스폰한다. V3 플레이어 프리팹은 공용 NGO 베이스의 변형이다. 씬 동기화, NetworkPrefab 에셋과 직렬화된 NGO 프리팹 목록을 함께 유지한다.

V3의 NGO 연결 페이로드는 지난번 사용한 닉네임을 기본값으로 제공하는 메뉴에서 받는다. 승인 콜백은 UTF-8과 2~12 표시 문자 규칙을 검사하고 승인한 닉네임을 캐릭터에 복제한다. 플레이어 식별과 복구에는 기존 서버 슬롯과 NGO ID를 사용한다. 캐릭터가 보고한 기존 Ready의 서버 승인 결과는 대기실에서도 읽을 수 있다.

## 권한과 RPC

| 데이터 | 결정권과 동기화 |
| --- | --- |
| 일반 캐릭터 | 소유자가 Input System과 CharacterController로 이동하고 `OwnerNetworkTransform`이 복제한다. 서버는 받은 위치 표본으로 거리와 결승을 검사한다. 소유자 이동이 정직하다는 전제를 사용한다. |
| 막대 | 소유자는 자기 카메라를 기준으로 Pivot의 수평 이동 또는 Orbit의 방위·고도 입력을 보낸다. 서버가 현재 역할과 revision, 지면 지지, 두 플레이어의 캡슐 이동 및 역할 교대를 검증하고 양쪽 끝점을 하나의 스냅샷으로 동기화한다. Pivot 달리기는 서버의 일반 스태미나 소비 규칙을 사용한다. 그립 중 일반 이동을 일시 정지하고 놓으면 복귀한다. |
| 복로 산악 발사 | 착지 링은 충전 중인 소유자에게만 보인다. 서버가 발사 티켓과 발사 입력을 승인하고 소유자의 이동 이후 서버가 지면 지지를 확인해 착지를 확정한다. |
| 다리·강 | 서버가 운반 승인·설치·붕괴·선체·위험 판정·순위·복구를 관리한다. 탑승자는 복제된 선체로부터 좌석 자세를 계산한다. 각 피어는 같은 서버 장애물 목록을 표시하고 선체 스냅샷의 피해 횟수와 서버 시각으로 피격 표시를 계산한다. |
| 성채·지하 | 서버가 슬롯·거리·진행 단계·입력 revision과 발판 기한을 검증한다. 비공개 힌트와 번호는 해당 소유자에게만 전달한다. 공통 퍼즐 상태와 기한을 복제한다. 문 발판은 서버가 승인한 문양으로 상판을 내리고, 하수도 벽판은 양쪽 입력을 승인하고 단계를 넘긴 뒤에야 순서를 표시한다. 복로 하수도는 다음 문양을 검증해 승인한 버튼의 서버 시각과 슬롯별 진행을 복제한다. 지하 함정의 전조와 공격은 공유 시작 시각을 사용하며 피격은 서버가 판단한다. |
| PvP·스태미나 | 서버는 입력 소유자, 생명 ID, 상태, 거리, 방향, 시야, 쿨다운과 잠금을 확인한다. 공격 요청과 0.18초 뒤 충돌 검사에 서버 시간을 사용한다. 준비와 피격 시각 및 잡기 관계를 복제해 양쪽 피어에서 자세를 표시한다. 승인 충격은 피해 소유자가 적용한다. 점프는 로컬 선행 입력과 서버 소비 검증을 사용하고, 달리기는 짧은 서버 임대로 유지한다. |
| 보석·결승 | 서버가 보석 상태·소유자·revision과 승자·시간을 복제한다. 같은 revision의 동시 픽업은 첫 유효 요청만 수락한다. 드롭은 다음 서버 프레임부터 획득할 수 있다. 같은 프레임의 사망은 피격 드롭을 덮어쓴다. |

서버는 경기 시작 시 슬롯별 망토 색상 인덱스를 골라 복제한다. 망토 색상은 리스폰 후 유지되고 같은 방에 재접속하면 기존 슬롯에서 복원된다.

복로 다리에서 서버는 두 플레이어의 복제된 발 위치를 다리 폭과 데크 높이 범위로 제한한 뒤 저장 판자 순서에 대응시킨다. 각 슬롯의 앞뒤 3칸 안에서 기존 붕괴 대상만 선택하며, 주황색 전조와 영구 제거를 각각 동기화한다. 전조 0.65초는 최초 접근에서 한 번 시작한다. 제거된 판자도 동일한 경로 인덱스를 유지한다.

왕로 다리의 목재 이동에서 서버는 다음 손잡이 위치도 기존 2.5m 보유 범위 안에 있는지 확인한다. 다음 이동으로 한 피어의 복제 위치가 범위 밖이 될 경우 현재 목재 위치를 유지하고 새 위치를 기다린다. 어느 보유자가 현재 손잡이에서 이미 범위를 벗어난 경우에는 기존대로 목재를 반납 처리한다. 설치에는 이전과 동일한 양쪽 승인, 손잡이 위치 및 설치 위치 검사가 필요하다.

리스폰 후 이전 생명 ID의 PvP·스태미나·보석 명령은 무효화된다. 진단 HUD 및 테스트용 Return 전환은 Editor/Development 빌드에서 사용한다. 정식 복로는 공동 봉인 이후 보석 픽업으로 전환한다.

막대 시작 봉우리, 성채 지하문 양쪽, 복로 다리 진입부의 체크포인트는 서버가 현재 Phase, 진행 조건, 복제된 위치와 지면 지지를 검사한다. 서버는 플레이어 슬롯에 맞는 복구 위치를 저장하고 기존 `CheckpointName`을 두 피어에 복제한다.

## 연결 끊김과 재접속

Client가 떠나면 Host의 대기실에 상대 재입장 안내가 표시되고 진행은 서버에 남는다. 막대와 운반, PvP 잡기는 해제한다. 세션이 살아 있는 동안 기존 방 코드와 로컬 닉네임으로 수동 재입장하면 새 NGO client ID를 받을 수 있으며 서버의 슬롯/상태와 구간별 체크포인트를 복구한다. 성채에서는 왕로 상류 부두, 복로 지하문 인근을 사용한다. 개인 체크포인트와 왕로 뗏목 공동 복구는 각 시스템이 결정한다. Host가 방을 닫으면 Client를 메인 메뉴로 보내고 새 방을 안내한다. 통신 단절로 방 상태가 불명확하면 기존 코드를 채운 참여 화면으로 돌아간다.

### 방 종료 신호와 정리 순서

- 명시적으로 나갈 때 NGO의 ReliableSequenced 메시지를 현재 연결로 보낸다. Host는 방이 닫힌다는 신호를 보내고 새 연결 승인을 중단한다. Client는 서버 ID에서 받은 신호만 방 종료로 인정하고 자신의 퇴장 메시지로 수신을 확인한다. 서버는 메시지를 보낸 연결만 정리한다. 일반 Client 퇴장도 이 경로를 사용하며 Host 방은 유지된다.
- Host는 상대 연결이 제거되거나 최대 2초가 지나면 Multiplayer Services의 `LeaveAsync`로 NGO, Transport, Relay 및 방을 정리한다. Client의 명시적 퇴장도 상대의 연결 정리 또는 같은 기한을 기다린 다음 자신의 세션을 정리한다. 방 종료를 수신한 Client에게 연결 종료 콜백이 오지 않으면 2초 뒤 로컬 NGO 종료를 요청한다. 이 시간은 종료 메시지 교환에만 적용하며 저장된 30초 UTP 단절 타임아웃은 유지한다.
- 수신한 방 종료 신호 또는 기존 NGO 종료 사유를 `HostLeft`로 분류한다. 확인된 사유 없이 연결이 끊기면 `Connection`과 수동 재입장 안내를 사용한다. NGO 시작마다 수신 상태와 메시지 핸들러를 초기화한다. 비동기 종료 대기는 이전 세션 객체에 한정하고 새 생성·참가 전에 이전 Multiplayer Services 정리를 기다린다. 방 단위 종료는 같은 Relay 연결을 유지하는 재경기와 독립적이다.

## V3 대기실 시작 승인

`WaitingForPlayers`에서 서버는 슬롯 1 Client의 Ready/취소만 수신한다. Host 슬롯 0의 시작 요청은 두 승인 슬롯의 PlayerObject가 연결되어 있고 현재 Client 승인 ID와 Ready가 일치할 때 한 번만 `Preparing`으로 전환한다. 서버에서 먼저 처리된 요청이 경합을 결정한다. Ready 취소가 먼저 승인되면 시작을 거부하고, 시작이 먼저 승인되면 이후 취소는 대기실 단계를 벗어나 거부한다.

## 서버 연출 구간

`GameStateManager.Transition`은 서버가 쓰는 단일 스냅샷이다. 종류, 증가하는 일련번호, NGO 서버 시작 및 종료 시각, 월드 위치, 필요 시 최초 획득 슬롯과 보석 revision을 복제한다. 두 피어는 NGO의 추정 서버 시각으로 남은 시간을 계산하며, 실제 표시 프레임은 복제 지연과 각 피어의 프레임 간격에 따라 달라질 수 있다.

- Runtime Ready와 월드 준비가 모두 충족된 `Preparing`에서 시작 0.75초 전에 구간을 복제하고 3초 카운트다운을 표시한다. 종료 시 `Outbound`가 되며 `courseStartedAt`에 카운트다운 종료 시각을 저장한다. 시작 안내는 이후 최대 0.85초 표시한다.
- 봉인 승인 뒤 1.5초 동안 `SealPending`을 유지한다. 최초 보석 획득에서 `Return`으로 전환하고 2초간 입력을 제한한다. 경기 시간은 두 구간에서도 계속 흐른다.
- 신규 RPC는 기존 소유자·생명·기믹 revision 및 거리 확인과 함께 연출 세대 및 서버 기한을 확인한다. 일반 이동 위치는 기존 소유자 Transform 동기화를 사용한다. 소유자가 로컬 이동 입력을 제한하고 서버는 점프·달리기와 위치를 사용한 행동을 검사한다.
- 시작 전이나 카운트다운 중 참가자가 종료하면 시작 승인과 Ready를 초기화하고 대기실로 돌아간다. 이미 진행 중인 방은 기존 슬롯·Phase·체크포인트·보석 복구와 서버 종료 시각을 유지한다. 재입장 시 현재 서버 시간에 해당하는 구간만 표시한다. 세션을 나가면 표시와 효과음을 정리하며 새 방은 초기 상태로 시작한다.

## 결과와 재경기

- 결승 승인 당시의 NGO 승자 ID와 서버 슬롯을 함께 기록한다. 같은 경기의 Client가 다시 참가해 새 NGO client ID를 받아도 결과는 서버 슬롯으로 복원한다. 두 피어는 같은 시작·종료 시각에서 정지된 시간을 계산한다.
- Finished에서 연결·스폰·런타임 준비를 확인하고 참가자 슬롯별 동의를 복제한다. 중복 요청은 상태에 영향을 주지 않는다. 양쪽 동의가 모이면 서버가 두 참가자의 상태를 한 번 더 확인하고 새 경기 씬을 로드한다. 그 전에 연결이 끊어지면 동의를 초기화한다. 승인 이후 단절이면 남은 접속으로 재구성을 마치고 대기실에서 상대 재입장을 기다린다.
- 같은 Relay 연결, 방 코드, 슬롯 및 승인 닉네임을 유지한다. 재구성 중 연결은 재시도 안내로 응답한다. 재구성에 실패하면 기존 방 종료 경로를 사용한다. 재구성 완료 후에는 같은 코드로 새 경기 상태에 참가하며 진행 중 재접속은 기존 구간별 복구 계약을 따른다.
- V3에서는 라이브 NGO 세션의 오브젝트 ID 재사용을 끈다. 새 GameState 오브젝트 ID가 경기 식별자다. 참가자, 경기·기믹 오브젝트를 교체하므로 이전 Ready, Start, 이동, 보석, 전환 및 상호작용 메시지는 폐기된 대상으로 향한다. 동의 요청은 자신의 경기 식별자도 명시한다.
- Client Ready, Host Start 및 Runtime Ready를 다시 충족해야 한다. 망토는 새 경기 시작 시 기존 규칙으로 다시 배정하며 같은 경기에서 재참가하면 슬롯의 색을 복원한다. Host가 방을 닫으면 기존 새 방 안내를 사용한다.
