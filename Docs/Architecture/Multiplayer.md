# V3 멀티플레이

## Relay와 NGO

두 프로세스는 별도 익명 Unity Authentication 프로필을 사용한다. Host는 Relay 할당 및 참가 코드를 만들고 NGO Host로 동작하며, Client는 같은 코드를 통해 Relay에 접속한다. Unity Services 설정이 공유 프로젝트에 연결되어 있어야 한다. 참가 UI는 레벨을 로드한 뒤 열리며, 두 피어는 씬 바인딩, 승인된 스폰 적용, 네트워크 캐릭터와 카메라 초기화가 완료되면 서버에 Ready를 보고한다. 서버는 현재 연결된 두 플레이어의 Ready를 확인하면 한 번만 경기를 시작한다.

`MultiplayerSessionManager`는 방과 연결을 관리하고, `NetworkSpawnCoordinator`가 플레이어 오브젝트를 스폰한다. V3 플레이어 프리팹은 공용 NGO 베이스의 변형이다. 씬 동기화, NetworkPrefab 에셋과 직렬화된 NGO 프리팹 목록을 함께 유지한다.

## 권한과 RPC

| 데이터 | 결정권과 동기화 |
| --- | --- |
| 일반 캐릭터 | 소유자가 Input System과 CharacterController로 이동하고 `OwnerNetworkTransform`이 복제한다. 서버는 받은 위치 표본으로 거리와 결승을 검사한다. 소유자 이동이 정직하다는 전제를 사용한다. |
| 막대 | 서버가 그립·회전·지지·충돌·역할 교대와 revision을 검증하고 하나의 스냅샷으로 양쪽 자세를 동기화한다. 그립 중 일반 이동을 일시 정지하고 놓으면 복귀한다. |
| 다리·강 | 서버가 운반 승인·설치·붕괴·선체·위험 판정·순위·복구를 관리한다. 탑승자는 복제된 선체로부터 좌석 자세를 계산한다. |
| 성채·지하 | 서버가 슬롯·거리·진행 단계·입력 revision과 발판 기한을 검증한다. 비공개 힌트와 번호는 해당 소유자에게만 전달한다. 공통 퍼즐 상태와 기한을 복제한다. |
| PvP·스태미나 | 서버는 입력 소유자, 생명 ID, 상태, 거리, 방향, 시야, 쿨다운과 잠금을 확인한다. 승인 충격은 피해 소유자가 적용한다. 점프는 로컬 선행 입력과 서버 소비 검증을 사용하고, 달리기는 짧은 서버 임대로 유지한다. |
| 보석·결승 | 서버가 보석 상태·소유자·revision과 승자·시간을 복제한다. 같은 revision의 동시 픽업은 첫 유효 요청만 수락한다. 드롭은 다음 서버 프레임부터 획득할 수 있다. 같은 프레임의 사망은 피격 드롭을 덮어쓴다. |

리스폰 후 이전 생명 ID의 PvP·스태미나·보석 명령은 무효화된다. 진단 HUD 및 테스트용 Return 전환은 Editor/Development 빌드에서 사용한다. 정식 복로는 공동 봉인 이후 보석 픽업으로 전환한다.

막대 시작 봉우리, 성채 지하문 양쪽, 복로 다리 진입부의 체크포인트는 서버가 현재 Phase, 진행 조건, 복제된 위치와 지면 지지를 검사한다. 서버는 플레이어 슬롯에 맞는 복구 위치를 저장하고 기존 `CheckpointName`을 두 피어에 복제한다.

## 연결 끊김과 재접속

Client가 떠나면 플레이가 두 번째 피어를 기다리고 진행은 서버에 남는다. 막대와 운반, PvP 잡기는 해제한다. 세션이 살아 있는 동안 기존 방 코드로 재입장하면 새 NGO client ID를 받을 수 있으며 서버의 슬롯/상태와 구간별 체크포인트를 복구한다. 성채에서는 왕로 상류 부두, 복로 지하문 인근을 사용한다. 개인 체크포인트와 왕로 뗏목 공동 복구는 각 시스템이 결정한다. Host가 떠나면 양쪽이 로비로 돌아가며 새 방 코드를 생성해야 한다.
