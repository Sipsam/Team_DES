# V3 mountain traversal testing

Open `Assets/Game/Level/Testing/MountainTraversalTest.unity` on its own and press Play. The menu **Tools > Twin Edge > V3 Traversal > Open Test Scene** opens it exclusively after Unity's normal unsaved-scene prompt. Do not run concurrently with the source blockout or networking scenes.

WASD moves, Space jumps, mouse looks, Q toggles first/third person. Esc releases the pointer; right-click captures it. Tab cycles targets, Enter attempts an experimental arc. R returns to the last sampled safe summit, Shift+R to Start. F5 saves. With the pointer released, use the HUD to choose source/target, perform an explicitly labelled setup respawn, change preset or tune hypotheses. Setup respawns are excluded from traversal attempts. Live hypothesis sliders require **Apply capsule / recompute graph and samples** to refresh static graph/surface estimates. Runtime movement speed and arc controls take effect on the next movement/launch.

Sparse/Balanced/Dense retain 15/20/27 of the original authored small peaks, plus Start and Final. Reduced presets use deterministic farthest-point spatial coverage seeded by Start/Final, with ordinal ID ties; selection is not a reachability guarantee. They reuse exact authored peak dimensions and the existing V3 terrain builder on transient configuration copies. Dense references the original saved mesh. Serialized IDs, variant meshes and materials are shared test assets; source config/scene/Generated/Manual are never edited. The setup adapter calls the existing private BuildTerrain method and fails explicitly if its signature changes. No generator rewrite or scene regeneration is performed on the original.

The capsule copies the network prefab's 2m height and 0.45m radius. Defaults 5m/s, 1.5m jump, gravity 20 follow PlayerMovement, but remain prototype hypotheses. The controller has no network, raft, puzzle, gem, stamina or combat dependencies. Camera spherecasts avoid terrain clipping; human camera usability remains to be assessed.

The planning PDF specifies alternating two-person pivot/circumference movement with temporary circular support outbound, and individual charged elastic launches on return. The test parabola implements neither formal mechanic. Its envelope, lift and duration are editable hypotheses. CharacterController movement is subdivided into <=0.2m collision steps; an attempt must physically contact the intended summit with supported footprint/headroom. Collision, wrong/unsafe surface, falling, timeout and cancellation are recorded. No target teleport counts as success.

Editor gizmos show IDs, Start/Final, directed-envelope candidates (cyan), rejected source links (red), sampled landing cells and two capsule envelopes. Toggle these on the test component. Static graph paths include fewest moves, conservative landing/distance/height heuristic, height preference, left/right preference and reverse route. These can coincide; branch count means outdegree >=3, not a count of all simple paths. Pair statistics include all directed pairs; they are not measured jumps. No graph edge certifies an unobstructed arc or actual pole reach.

Landing sampling uses the actual MeshCollider: 1.5m grid, <=45 degree center/ring slopes, 12 perimeter support rays at capsule radius plus 0.4m margin, <=0.35m ring height variation, and capsule headroom. It estimates area from sample counts, not exact mesh polygon integration. Reported edge clearance is a tested minimum footprint radius, not the true nearest boundary distance. Two separated supported capsule footprints are occupancy evidence only; moving, turning, slipping and two-person interaction still require human tests. The low connected geology is excluded by summit-relative kill height and non-landing-ground timeout.

JSON sessions save automatically after attempts and on stop, and via F5, under `Docs/Development/Level/V3/TraversalTests/` (local, ignored). They contain source hashes, parameters, static snapshots, per-attempt evidence and grouped preset/route/target/outcome statistics. Zero attempts means failure rate is unmeasured. Visibility and complexity stay unmeasured until human observation. Optional local implementation/verification evidence lives beside these files; this guide does not require it on a fresh clone.

Automated setup check: Unity `-batchmode -projectPath <project> -executeMethod TwinEdge.Levels.Testing.Editor.TraversalSetup.Batch -quit -logFile <ignored-path>` on a fresh setup only. It refuses to overwrite the test scene. Runtime smoke: `-batchmode -projectPath <project> -executeMethod TwinEdge.Levels.Testing.Editor.TraversalSmoke.Run -logFile <ignored-path>` (no `-quit`; the check exits itself). Create the ignored log directory first. Runtime smoke is automated controller evidence, not human play acceptance.
