# Logical Workers

[AGENTS](../../AGENTS.md#task-dispatcher) selects the path and [Domain](../../AGENTS.md#domain-routing). Each assignment pairs a responsibility with one or more affected Domains. For example, Diagnose + Rendering uses the Rendering entry points and the Diagnose profile. The current Codex carries out the assignments in one session and pulls in relevant references as needed.

Give each tracked subtask a writable scope. Sequence edits to shared files and reuse existing changes. Check prerequisites before downstream work. If one subtask fails, preserve completed results with matching inputs, block its dependents, and continue unaffected work in the same session when useful. Diagnose before retrying and rerun only checks whose inputs or conclusions could have changed. Only top-level Finalize commits and pushes after the task meets its required checks and completion conditions.

## Task packet and result

Use a compact packet for tracked Complex subtasks. Keep it inline in the current session or [CURRENT_TASK](CURRENT_TASK.md#state-and-handoff) when needed for recovery. Link to source, contracts and prior results. Fast and Standard use ordinary task context.

- **Packet** — task or subtask ID, objective, assigned Worker, affected Domain, required context references, read and write scope, dependency IDs, constraints, required checks and completion criteria. A subtask may inherit shared constraints and validation rules by reference.
- **Result** — status, key findings, changed or affected files, check results with tested source or build, risks or blockers, evidence references and next action. Omit empty fields when the result is unambiguous. Keep detailed logs in ignored evidence and carry forward only the relevant facts.

## Reasoning and execution costs

Use Low or Medium for result summaries and the registry recommendations for other work. Decompose only when it helps control dependencies, write scope, validation or recovery. Keep large searches for cases that scoped symbol or path lookups cannot resolve. Reuse reads, code and evidence after checking inputs. Use Git, PowerShell and Unity for deterministic work. Keep progress updates to decisions, findings and blockers, with large logs in ignored evidence. Consider a summary mode or supporting script only for demonstrated cost, and preserve existing script interfaces.

The V2 audit verified Rider MCP repository discovery and a scoped symbol lookup on the Windows workspace. JetBrains documents user-controlled model and reasoning selection and a session context indicator with used tokens and percentage. These are client UI capabilities. The audited agent session exposes no verified Worker-triggered model or reasoning switch, per-Worker context isolation, or usage reader for the live Rider session. Keep the active session settings.
